# native_ffi: real-time note detector (Rust)

`native_ffi` listens to the microphone, follows the currently loaded score note by note, and reports each played note (measured pitch, start/end in the score's clock, loudness) to the Flutter app through flutter_rust_bridge. It is a score follower, not a free transcriber: it only asks "is this expected note sounding now?", so with no piece loaded nothing is detected.

Crate: `native_ffi` 0.1.0, Rust edition 2024, built as `lib` + `cdylib` + `staticlib` ([Cargo.toml](../../native_ffi/Cargo.toml)). flutter_rust_bridge is pinned to `=2.13.0` (same pin in `frontend/pubspec.yaml`).

## Data model

### Input: `PieceData` (JSON passed to `init_session`)

```json
{
  "piece_name": "three notes (A4, C5, E5)",
  "curr_phase": 0,
  "instrument": null,
  "curr_music_phrase": 0,
  "timing": { "bpm": 60.0, "beat_unit": 4 },
  "notes": [
    { "note_id": 1, "pitch_hz": 440.0, "start_time_ms": 0.0, "end_time_ms": 1000.0,
      "duration_ms": 1000.0, "is_end": false, "vibrato_depth": null,
      "pedal_action": null, "has_accent": null, "markings": null }
  ]
}
```

- Required (non-`Option`): `piece_name`, `curr_phase` (u8), `curr_music_phrase` (u32), `timing.bpm` (f32), `timing.beat_unit` (u32), `notes`, and per note `note_id`, `pitch_hz`, `is_end`. `Option` fields may be null or omitted.
- `curr_phase` must be 0 or 1; for any other value no tracker is built and audio is ignored.
- `instrument` is one of `Violin, Viola, Cello, Piano, Guitar, Trumpet, FrenchHorn, Clarinet` or null. It is only used to pick matching `NOTE_TEMPLATES`.
- `timing` and `curr_music_phrase` are parsed but not used by detection.
- Notes without `start_time_ms` are dropped; the rest are sorted by start. A missing `end_time_ms` means "listen until start + 85 ms".
- The backend's `/api/score/process` uses `time_signature` instead of `beat_unit`, so the app builds `PieceData` itself (`toPieceData` in `frontend/lib/features/practice/Exercise.dart`).

### Output: `Notes` (one record per played note)

| Field | Output value |
|---|---|
| `note_id` | id of the score note it matched |
| `pitch_hz` (f64) | median of the pitches measured while it sounded |
| `start_time_ms`, `end_time_ms`, `duration_ms` (f32) | score-clock times (see Clock anchoring); duration = end − start |
| `is_end` | copied from the score note (last note of a phrase) |
| `vibrato_depth`, `pedal_action`, `has_accent`, `markings` | always `null` (not detected) |
| `volume` (f32, 0..1) | loudest 50 ms RMS window in the note's span, linear in dB from −60 dBFS (0.0) to 0 dBFS (1.0, AES17: full-scale sine = 0 dB). Device-relative, not calibrated; mapping to pp..ff is the backend's job. `null` on score notes |

The same struct is used for score notes (input) and detections (output).

## Public API

Bridged to Dart (inline `mod api` in `lib.rs`; Dart side in `frontend/lib/src/rust/api.dart`):

| Rust | Dart | Behaviour |
|---|---|---|
| `init_session(json_data: String)` | `initSession(jsonData:)` | Parses `PieceData` (`unwrap()`: invalid JSON panics), waits up to 3 s for the previous recording's processing thread if the mic is closed, stores the piece, bumps `PIECE_GENERATION`, clears `USER_DATA`. Call before every recording. |
| `notes_stream(sink)` | `notesStream()` | Registers the `StreamSink<Vec<Notes>>`. Each time notes finish, the whole undelivered buffer is sent and cleared. |
| `get_user_data() -> String` | `getUserData()` | JSON of notes not yet delivered (`null` if none); waits for the processing thread first if the mic is closed. Used on stop to recover the last note. |

Plain C exports (`#[frb(ignore)]`, `#[unsafe(no_mangle)]`), wrapped in `frontend/ios/recording_bridge.c` and called via `dart:ffi` from `frontend/lib/integrations/audio/Audio_Native.dart`:

| Rust | C wrapper | Behaviour |
|---|---|---|
| `listen_audio() -> i32` | `start_recording()` | Opens the default input device and spawns the `audio-processing` thread. Returns 0 (also if already recording) or an error code. |
| `stop_audio()` | `stop_recording()` | Drops the stream and returns immediately; the thread drains queued audio and closes notes still sounding. |
| `audio_status() -> i32` | `recording_status()` | 0 or the latest problem code since the recording started. |
| `audio_error_message(buf, cap) -> usize` | `recording_message()` | Copies the message as NUL-terminated UTF-8, cut on a char boundary. |

Status codes ([audio.rs](../../native_ffi/src/audio.rs)): 1 no device, 2 config unreadable, 3 unsupported sample format, 4 open refused, 5 start failed, 6 stream error, 7 overrun (audio dropped), 8 worker failed / previous still running / panic, 9 stalled (no audio for 2 s). Warnings (analysis continues): 100 pure digital silence for 1 s, 101 pitch network unavailable (DSP fallback). A warning never replaces an error. All C exports and the worker run under `catch_unwind`; a panic becomes code 8.

## Pipeline

```
cpal callback ─▶ bounded queue (2048 chunks) ─▶ audio-processing thread ─▶ USER_DATA / notes_stream
(downmix only)  ◀── 64 recycled buffers ────     evidence (neural or DSP) → NoteTracker → volume
```

1. Audio intake ([audio.rs](../../native_ffi/src/audio.rs)). Device-native rate and format; any of cpal's sample formats is converted to f32 and averaged to mono. The callback never blocks and does not allocate once the buffer pool is warm; a full queue reports code 7. The worker watches for 1 s of exact zeros (100) and 2 s without chunks (9).
2. Follower. On the first frame after a piece is loaded (phase 0/1) a `NoteTracker` is built; a changed `PIECE_GENERATION` drops it, including unfinished notes of the old piece.
3. Evidence, neural (default, `USE_NEURAL = true`; [run_onnx.rs](../../native_ffi/src/run_onnx.rs)). Audio is resampled to 22.05 kHz (rubato) and Spotify's Basic Pitch "nmp" model (88 keys, A0–C8) runs on ~2 s windows via tract (pure Rust) every 16 frames (~186 ms). A frame (11.6 ms) is released 9 frames (~105 ms) after it was heard. Per expected note: confidence = key activation; dominance = activation over the strongest non-expected semitone neighbour. A DSP analysis centred on the same moment supplies the measured pitch and attack level. If the model fails to load, warning 101 and DSP mode.
4. Evidence, DSP ([dsp.rs](../../native_ffi/src/dsp.rs), [joint.rs](../../native_ffi/src/joint.rs), [templates.rs](../../native_ffi/src/templates.rs)). 4096-sample Hann-windowed FFT every 256 samples (~5.8 ms at 44.1 kHz; bins ~11.7 Hz at 48 kHz), only when some note is a candidate. Noise floor = median magnitude over 50–5000 Hz. Each frame is fitted jointly with every expected note plus its semitone neighbours (24 harmonics, 4 loudness bands, 100 KL iterations, or learned templates when available). Per note the analyser reports dominance over neighbours, share of the strongest fitted note, attack level from the newest 2048 samples, and the peak pitch by parabolic interpolation on log magnitudes.
5. Tracker ([tracker.rs](../../native_ffi/src/tracker.rs)). Candidates are notes whose window `[start − 85 ms, end + 85 ms]` (`TIMING_MARGIN_MS`) contains the current score time, or which are still sounding; a note stops being listened for when the next same-pitch note's window opens. Each note has its own state machine, so chord notes and overlapping notes do not interfere:
   - start: N-of-M frames passing start thresholds; stricter for a lone note than inside a chord (polyphony from the score);
   - sustain: lenient threshold (hysteresis); end after K consecutive missing frames;
   - repeated pitch: a note whose pitch is already ringing from an earlier same-pitch note starts only on a re-attack (level ×1.5 above its minimum);
   - neural mode stamps start and end where confidence crosses 75% of the note's own (decaying) peak.

   | | on | of window | off | start dom. single/chord | sustain dom. | start share | start/sustain conf. |
   |---|---|---|---|---|---|---|---|
   | `Thresholds::DSP` | 5 | 8 | 8 | 2.5 / 1.7 | 1.5 | 0.2 | — |
   | `Thresholds::NEURAL` | 2 | 4 | 4 | 1.5 / 1.5 | 1.0 | — | 0.15 / 0.1 |

6. Clock anchoring (`ANCHOR_CLOCK = true`, `NoteTracker::anchored`). The app opens the mic during the count-in, so stream time ≠ score time. Until the opening note(s) (those within 50 ms of the first scored note) are heard, only they are listened for, at any time; the first one heard sets score time = its scored start, and all later notes are timed relative to it.
7. Volume ([volume.rs](../../native_ffi/src/volume.rs)). `LevelLog` records RMS dBFS of 50 ms windows every 25 ms for the whole recording; each finished note gets the loudest window overlapping its span (score times shifted back by the clock offset).
8. Publish. Finished notes are appended to `USER_DATA` and, if a sink is registered and accepts, delivered and cleared. On stream close, `finish()` closes notes still sounding. Old README measurements: delivery median ~0.5 s after the note ends (neural), ~150 ms (DSP).

## Known limitations

- Score-following only: no piece loaded, or `curr_phase` 2/3, means no detection.
- Nothing is reported until an opening note is heard; a player who skips it gets no notes. After anchoring, notes more than 85 ms off their scored window are missed.
- Neural mode only covers the 88 piano keys (A0–C8): `neural_evidence` returns no evidence for pitches outside that range.
- DSP mode: below ~A#1 (58 Hz) a note's harmonics sit within the window's blur of its neighbours'.
- CPU: neural evidence used 52–54% of one core in the dev container (old README; not measured on phones). A device ~1.9× slower would fall behind; `RUN_EVERY_FRAMES = 32` halves the cost for ~90 ms more delay.
- Ends run late on sustained/ringing notes (median end +92 ms on MAESTRO, long tail around +400 ms).
- `vibrato_depth`, `pedal_action`, `has_accent`, `markings` are never filled in on detections.
- Templates cannot be loaded from the app: there is no API that sets `NOTE_TEMPLATES`, and the app sends `instrument: null`. Only the harnesses use them.
- `init_session` panics on malformed JSON.
- Loading another piece mid-recording drops the old piece's unfinished notes.
- iOS only: Android is not wired up; the macOS app does not link the library.
- `volume` is device- and distance-relative.

## Discrepancies with the old READMEs

1. "How detection works" (1024-sample window every 128 samples, RMS ≤ 0.0075 gate, loudest of three bins nearest the target, ~47 Hz bins, "loudest candidate wins") no longer matches code: DSP uses a 4096/256 Hann FFT, a median noise floor, harmonic combs with a joint fit, and per-note tracks with chord-aware thresholds; the default evidence is the neural model.
2. Known limitations "coarse 47 Hz resolution", "one note at a time", "fixed volume threshold" and "`get_current_targets` clones every note" are outdated; `get_current_targets` does not exist.
3. The 2026-09-30 change log names `process_dsp`, `create_stream`, `run_fft`, `NoteTrack`; none exist in the current code (historical only).
4. Test table names `test_c4_pitch_detection`, `a_note_ending_does_not_freeze_the_audio_thread`, `in_tune_notes_read_in_tune_at_48k`, `a_wrong_note_is_reported_in_the_right_direction`, `median_of_what_was_heard`, `a_ringing_note_does_not_start_the_next` do not exist. Current DSP tests are e.g. `test_c4_detected_with_accurate_pitch`, `test_every_note_of_a_chord_is_detected`, `test_wrong_note_is_rejected_inside_a_chord`.
5. "Every field must be present": serde treats missing `Option` fields as `None`, so only non-`Option` fields are required. Invalid JSON panics (`unwrap`) rather than failing cleanly.
6. `src/api/` (`greet`, `init_app`) is a leftover template: `lib.rs` declares an inline `mod api { … }`, so `src/api/mod.rs` is never compiled and `frb_generated.rs` only wires `get_user_data`, `init_session`, `notes_stream`.
7. `build_rs.sh` builds `aarch64-apple-darwin` but copies the iOS device library to `frontend/ios/libnative_ffi_desktop.a`; the iOS Xcode project references only `libnative_ffi.a` and `libnative_ffi_sim.a`.
8. Cargo.toml lists `pitch-detection` and `spectrum-analyzer`, which no source file uses.
